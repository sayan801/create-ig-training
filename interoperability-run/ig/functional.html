Use cases

  1. Plan: the runner has a preventive care plan (vital signs before and after, join the run) and an appointment for the run at a given location.

  2. Baseline before the run: the runner records resting heart rate and SpO2 (phase pre-run).
  3. During the run: the wearable streams or stores heart rate and SpO2 (phase during-run).
  4. Recovery after the run: the runner records heart rate and an optional single-lead ECG strip (phase post-run).
  5. Run summary: an exercise session observation records where the run took place, how long it lasted, the distance and the average pace.
  6. Conditions: an environmental conditions observation on the course records air temperature, humidity and, for swimmers, water temperature.
  7. Participant report: a report (DiagnosticReport) brings together the vital signs, ECG, session and conditions with a short conclusion.
  8. Event dashboard: the organisers collect the observations from all runners of an event (WGM, Connectathon, DevDays) and show, for example, average heart rate per phase.

Data flow

Wearable -> vendor app / phone -> FHIR client -> collector FHIR server -> event dashboard

Each observation carries the Interoperability Run context extension:

  • eventType: WGM, Connectathon, DevDays or other (value set)
  • eventName: for example "HL7 Europe WGM Malaga 2026"
  • phase: before, during or after the run (value set)
  • location: the run course (IRunLocation)

Resource overview

CarePlan (preventive check-up)
  |-- activity -> Appointment (the run) -> Location (course)
  |-- activity: heart rate, SpO2, ECG
Observations (HR, SpO2, ECG, exercise session) -> Patient (runner), Device (wearable), run context -> Location
Observation (environmental conditions) -> Location (course)
DiagnosticReport (participant report) -> all of the above observations
